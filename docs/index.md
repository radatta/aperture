# Aperture — docs index

Personal life-OS PWA. Web-first, installable. AWS-native serverless.

**Build status (2026-09-07):** V1_PLAN phases **0–14 built**, all six packages green (260 tests). Custom domains are **live on both stages** (arch/INFRA §8). Recruiting/LeetCode capture is verified end-to-end on dev and awaiting its merge to `main` ([recruiting/](areas/recruiting/index.md)). The one open item that isn't code is the **9.2 stub-validation gate** — dogfood a real morning + night. See V1_PLAN's build-status block.

Docs are grouped: **product/** (what & why + rules), **arch/** (how it's built + ops-to-be), **areas/** (per-domain design docs), **ops/** (sandbox runbooks). `V1_PLAN.md` stays at the top level as the whole-v1 roadmap.

## areas/ — per-domain design docs
- **[areas/tasks/due-dates.md](areas/tasks/due-dates.md)** — **task due dates**: a day-granular `dueDay` (when it's due, distinct from `taskPlans.day`, when I'll work it), free metadata outside the estimate lock. Holds the decision log (why enrichment-only, why no overdue tally, the sort-is-a-hint rule) and the build record. The no-scold posture applied to deadlines.
- **[areas/tasks/bulk-add.md](areas/tasks/bulk-add.md)** — **bulk add tasks**: paste many lines → many backlog tasks, with an inline `~estimate #category due:date` grammar behind a ` | ` separator and a live red/gold preview. The operator is Claude, so the grammar is strict and concrete (ISO dates, no shortcuts) — **read the "Operator reference" section before generating a bulk paste**. Holds the decision log (explicit separator, best-effort batch write, no silent rewrites) and the build record.
- **[areas/tasks/attachments.md](areas/tasks/attachments.md)** — **task attachments**: files on a task (receipt, spec, screenshot) — the first feature that stores **bytes**. A metadata child (`attach#<taskId>#<id>`) in DynamoDB plus a new *precious* S3 Files bucket, with **presigned-URL** transport so bytes go browser↔S3 directly and the JSON RPC edge never carries binary. Holds the decision log (presign over proxy, the pending→ready status, the caps, orphan-on-delete, object-scoped IAM) and the build record.
- **[areas/home/right-now.md](areas/home/right-now.md)** — the **daytime home**: a "Right now" card (the Big 3 = top of today's plan, with the in-progress task as a hero showing a calm count-up vs its estimate, a lighter "Also today" lane, and a "what's next?" prompt with no auto-advance) over a capped, gentle "Coming up" deadline radar. Replaces the old today-tasks + focus cards. Holds the decision log (plan-derived focus, count-up not countdown, no over-run nudge, "Focus this" as the only way to choose the Big 3, radar daytime-only) and the build record.
- **[areas/home/rolls.md](areas/home/rolls.md)** — **Rolls**: deadline-free ongoing efforts (LeetCode daily, study) with a **forgiving momentum "contact sheet"** — a dot grid that only fills, no resetting streak/red/score. A "rep" is a completed task tagged with the roll (derived, never a counter); the morning picker drops a rep onto today's plan, which flows into the daytime Right-now lane. Holds the decision log (derive-not-count, forgiving grid, distinct-from-Habits, not-a-series, dedicated `pickRollToday`) and the build record.
- **[areas/recruiting/index.md](areas/recruiting/index.md)** — the **LeetCode attempt-capture** module (`/recruiting`): the passive Firefox extension that mirrors LeetCode's own submit/check calls, why metadata comes from the server-rendered DOM rather than GraphQL, the device-token ingest path (scoped to the one write method) versus the JWT read path, and **the identity seam between them — `DEVICE_USER_ID` must equal your Cognito `sub` or capture silently writes rows the page will never show**. Holds the operator checklist (two GitHub secrets + two vars, extension install) and **what local stub testing proves versus what only a dev deploy can**. Read before touching the extension or the ingest endpoint.
- **[areas/recruiting/story-bank.md](areas/recruiting/story-bank.md)** — the **Behavioral Story Bank**: a `stories` entity + a story-bank tab at `/recruiting/stories` holding ~8–12 competency-tagged STAR stories. Design record and build record — the data model, the product decisions with rationale (fixed six-tag union, structured-at-entry as the one deliberate exception, soft-delete, routed tabs), how the RPC/export/DDB/app layers are wired, the phased implementation plan, and the testing approach.
- **[areas/calendar/index.md](areas/calendar/index.md)** — **Google Calendar integration** (multi-account): connect personal + school accounts, read a morning "day shape" (longest free stretch + fragment count, not "hours free"), and write real events from tasks. The design record — why shape-not-hours, the two-grant multi-account model, the 7-day-token and silent-normalization traps, the account-aware gated `GoogleGateway` (parallel to the DDB `Writes` seam), the data model + SSM token scheme, the callback route + CloudFront query-string/`APP_URL`/SSM-IAM CDK gotchas, and delete-on-cancel with edit-sync as a named deferred gap.
- **[areas/calendar/research.md](areas/calendar/research.md)** — **the pre-build research** behind the calendar work: the behavioral-science finding that reframed it (retrospective calibration views don't change behaviour → the intervention belongs at estimate time), the four-piece vision (shape + commitment line **shipped**; estimate-time multiplier + night reconciliation are **PR-D**), the statistical trap (never bucket calibration by *actual* duration), and the "don't build" list (write-back, auto-scheduling, calendar grid, chronotype inference). Reconciled against what actually shipped in index.md.
- **[areas/mcp/index.md](areas/mcp/index.md)** — the **MCP server** (`/mcp`): one hosted endpoint that lets **Claude Code** read+write Aperture (tasks, calibration, LeetCode, calendar, attachments) via a static **agent token**, with **claude.ai** on the same endpoint via OAuth in phase 2. The design record — the credential-not-method auth fork, the "agent token is a full app session" ceiling and what it still can't do, the ~19-tool surface, the **hand-rolled (no-SDK) protocol** with its A/B justification, the second Lambda + `/mcp` CloudFront wiring, the operator checklist + **Claude-Code-header smoke** and stdio fallback, and the phase-2 OAuth façade. Read before touching the MCP surface or generating tool calls.
- **areas/calibration/** — (planned) per-course & intent-vs-actual calibration, exam-prep spacing, this-week's-dues. Design doc lands with that work.

## ops/ — sandbox runbooks
- **[ops/COI-SANDBOX.md](ops/COI-SANDBOX.md)** — the **runtime playbook** for running Claude Code on this repo inside an Incus container (day + night profiles). Opens with **Start here — the four things you ever do**: launch Claude, debug at the VM layer, debug inside the container, shut down — each with the exact commands and which of the three layers (Mac / Lima VM / container) to run them at. Then the Lima→Incus stack, one-time setup, the four config files, how to *end* a session (**exiting `coi shell` is what exports** — `coi shutdown` only deletes, and forces a resume that **forks** the session into a new picker entry; reattach with `coi attach` instead — verified 2026-09-07), the **port convention** (5173+ you, 6173+ container), **how to triage a frozen container from the audit log** (read `~/.coi/audit/<name>.jsonl` directly — `coi audit` has a read-path defect), **GitHub access inside the container** (no SSH agent → stale `origin/*` refs are the real hazard; read-only PAT setup, re-done after a VM rebuild, and why write access can't be safely scoped with a single identity), and a one-line index of every known failure signature.
- **[ops/COI-INCIDENTS.md](ops/COI-INCIDENTS.md)** — post-mortems for the sandbox failures that cost hours, kept out of the playbook so it stays short. `SIGABRT (134)` from pids-cgroup exhaustion; a 13-hour unattended run killed by `'Clamshell Sleep'` (and why `caffeinate` doesn't prevent it); the mount change that restarts the whole VM; the shared-`node_modules` hazard; the `limactl edit` typo that rebuilt the VM and deleted two Claude Code sessions (and why `~/.coi/` was never on the Mac), including the full zero-to-working VM bootstrap; the false-positive threat pause and the `coi audit` read-path defect; and the three container **kills** from `python3 -c` matching a hardcoded reverse-shell pattern gated only on the command containing a `:`. Includes the full log map, the ruled-out hypotheses, and the broken commands not to repeat.
