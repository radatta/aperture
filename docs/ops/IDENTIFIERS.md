# Identifiers — what may name the maintainer, and where

The repo is public with its real history (old commits keep what they had; history rewrites and PR-body edits were ruled out). Going forward, nothing tracked — code, docs, tests, fixtures — and no commit message, PR title or PR body carries a personal identifier. This doc is their one home; everything else points here.

What else stays out of public text — bio, money, school, family, quotes, real names — is [PUBLIC-CONTENT.md](PUBLIC-CONTENT.md).

## The two tiers

| Tier                     | What                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Where it may appear                                                                                        |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| **Blocked**              | the maintainer's name (either word, any case, as a whole word); the personal mailbox (every `+alias` — which is also today's contact and alert address, so code reads those from the config and docs say "the maintainer's email"); a concrete Mac home path (`/Users/<name>/…`); the Mac projects folder (its two-folder path anywhere, or its first folder alone under `~`, `$HOME` or `${HOME}`); the dev AWS account id; the prod AWS account id | only `identifiers.json` — and the one sim-runner line below. The prod id isn't even there: only its sha256 |
| **Public, from config**  | the domains (prod, dev, devb, apex), the repo slug, the GitHub login, the bundle / launchd prefix, the dev test user's address                                                                                                                                                                                                                                                                                                                       | code reads them from `identifiers.json`; docs and tests may name them                                      |
| **Never tracked at all** | the Mac repo path                                                                                                                                                                                                                                                                                                                                                                                                                                    | the main checkout's gitignored `.local/mac-root`                                                           |

The domain is the maintainer's name run together, and the GitHub login is a short form of it; neither matches the whole-word rule, so both stay usable.

**In prose:** the name is **"the maintainer"** (never quoted verbatim: paraphrase, keep the date — `(the maintainer, 2026-11-08)`). CLAUDE.md and runbooks addressed to Claude keep "the user" — the role the approval rules hang on. A tool description a model reads says "the user". The Mac path is **`<mac-repo>`**; a worktree is `<mac-repo>/.claude/worktrees/<branch>`. A made-up path in a test is `/Volumes/host/aperture`. Another project of the maintainer's is `~/<other-project>`.

## `identifiers.json`

At the repo root. Read at runtime, never imported (it sits outside every package's `rootDir`):

| Reader                                           | How                                                                                                      |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `scripts/src/identifiers.ts`                     | the loader, `REPO_SLUG`, the dev Cognito host, and the one rule set (`findIdentifiers`) every check uses |
| `cdk/src/config/identifiers.ts`                  | `ALERT_EMAIL` (prod alarms, cost and kill-switch mail) and the stage domains                             |
| devcheck, bot, mailroom, tower (`scripts/src/…`) | via `scripts/src/identifiers.ts` — origins, test user, repo slug, prod account by hash                   |
| `app/pwa/identityPages.ts`                       | fills `app/pages/{about,privacy}.html` (`{{maintainer.name}}`, `{{email.contact}}`) at build and in dev  |
| `scripts/board/devlock.sh`                       | `jq -r .repo`                                                                                            |

**Pinned literals.** What runs on the Mac from an installed copy can't read the checkout — launchd runs files fetched from GitHub, and the installed runner is the trust boundary (MAILROOM.md). So `tools/mailroom/{install.sh,jobs/open-pr.sh,jobs/sim.sh,bench/sim-bench.sh}`, `tools/macstats/install.sh` and `tools/raycast/aperture-add.sh` keep their values as literals, and `scripts/src/tracked-identifiers.test.ts` holds each equal to the config.

**The one blocked literal outside the config:** `jobs/sim.sh`'s `SIM_COGNITO_RE` pin (and its bench symlink). The sim checks its address bar against it before typing the test password, so it must not come from a file the container can write. Exempt by exact line, for the dev account id only. The mailroom fixtures write `@DEV_ACCOUNT@`; `run-fixtures.sh` fills it from that pin.

**The prod account id** stays out of tracked files entirely: `aws.prodAccountSha256` is how the tower labels its costs and how the checks catch it (any 12-digit run whose sha256 matches). A 12-digit id's hash isn't secret — it just keeps the literal out.

## The Mac repo path

One line in `<main checkout>/.local/mac-root`, written once on the Mac:

```
cd <mac-repo> && mkdir -p .local && pwd -P > .local/mac-root && cat .local/mac-root
```

Every worktree reads the same file (`scripts/src/mac-root.ts`: an absolute path of `[A-Za-z0-9_./-]`, no `..`). It feeds `pnpm mailroom open-pr`'s hand-off and renew/install lines, the tower's Mac-stats install line, and the SessionStart context (`.claude/hooks/load-context.sh` prints "Mac repo path: …"), so Claude can hand over real `cd` lines without the path ever being committed. Missing or malformed → `<mac-repo>` plus a one-line note on how to write it; CI never has it and needs none.

## The checks

One rule set, `findIdentifiers` in `scripts/src/identifiers.ts`, built from the config (no rule spells an identifier). The projects-folder rule is built from the gitignored `.local/mac-root` — the folders between the home directory and the repo, when there are two or more — so it runs only where that file exists: the container's commit hook, `pnpm bot push`, `open-pr`, `pnpm bot logs` and the container's run of the tracked-files test. CI and a fresh checkout have no such rule; the home-path rule still covers the absolute form there. An account id counts plain or dashed (`1234-5678-9012`); a home path counts JSON-escaped too, and so does the projects folder, in any case, including its home-relative form (its first folder alone under `~`, `$HOME` or `${HOME}`); `/Users/` is case-sensitive, so an API's `/users/me` passes. Hits report `path:line kind`, never the identifier.

| Where             | Check                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tracked files     | `scripts/src/tracked-identifiers.test.ts` scans every `git ls-files` path and its contents (binaries skipped). Its failure list is the worklist. CI runs the same test, minus the projects-folder rule.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Commits           | `.claude/hooks/precommit-guard.sh` → `scripts/src/identifiers-scan.ts`: the staged diff's added lines and new paths, plus the `-m` messages, WIP commits included. The hook runs before the command, so with a `git add` or `commit -a` in it the unstaged and untracked changes are read too. `git diff` runs with fixed prefixes and `core.quotePath=false`. Fails open on a checkout without the config (and has no projects-folder rule without `.local/mac-root`), no node, or a scan failure (exit 2). Fixtures: `.claude/hooks/testdata/precommit-fixtures.jsonl` (`"ids": true`).                                                                                                                                                                     |
| PR title and body | `pnpm mailroom open-pr` refuses `PERSONAL_IDENTIFIER` container-side, before anything is queued or a hand-off line printed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Dev-log fetch     | `pnpm bot logs` refuses `PERSONAL_IDENTIFIER` when `--filter`, `--query`, `--groups` or the run key (built from the branch name, which a local branch gets without the push scan) carries one, before it writes the loop-guard ledger or dispatches (the three flags before it even mints a token): a workflow run's inputs and name are public on a public repo. `--start` and `--end` go out normalised to ISO, so no text of theirs does. The message names where and the kind, never the value.                                                                                                                                                                                                                                                 |
| Push              | `pnpm bot push` refuses when a commit it's about to publish — one not yet on the base branch or on `origin/<branch>` — carries one in its message or its own diff (a branch's history is public from its first push, so a later commit that removes it isn't enough), when the branch name does, or when the branch has merge commits (their combined diff isn't scanned; rebase instead). **To fix a refused commit:** edit the line, `git commit --fixup=<sha>`, `git rebase --autosquash <base>` (no `-i` needed), then `pnpm bot push --after-rebase`; a line that conflicts in the rebase is fixed while resolving it. Commits already pushed before the rules aren't re-checked until the branch is rebased. The backstop for anything the hook missed. |

Not caught: a Mac username written outside a `/Users/…` path; the projects folder on CI or a checkout without `.local/mac-root`; a project or place name; a commit run as `git -C <other dir> commit` (the hook checks the session's own checkout) or `git --no-pager commit`; a commit that takes working-tree content by naming paths (`git commit -m x file`) or a `-F` message, at commit time — the push scan catches those; and a `.github/workflows/` branch the maintainer pushes, which skips the bot's push scan (the tracked-files test still runs on its PR). The review of each change still matters.
